# ETF 候选池相关性去重瘦身

把一个臃肿的 ETF/指数基金候选池压到「每个细分行业只剩一个代表」，并用相关性数据而不是名字来判定重复。

## 何时用

- 用户给了一个几十上百只的 ETF/股票池文档，要求"去冗余""瘦身""同一板块只留一个"；
- 轮动/多标的策略里同一风险被重复下注，需要清理；
- 想验证一个池子是否真的分散（算相关性而不是看名字）。

## 第 0 步：先和用户确认两个口径（必做）

不要自己拍板，这两点直接改变结果：

1. **收敛到哪一级**——同一指数/同细分行业，还是一个一级大类只留一只？
   （大类口径会砍掉 70%+，通常不是用户想要的。）
2. **组内保留谁**——流动性规模最优 / 跟踪误差最小 / 费率最低？

## 数据获取：源的选择与坑

| 源 | 结论 |
|---|---|
| **新浪** `ak.fund_etf_hist_sina` | **首选**。全历史，`amount` 字段单位是元，可直接算日均成交额。前缀 `sh`/`sz`。 |
| 东财 `ak.fund_etf_hist_em` | 常在本机 IP 连续请求 ~13 次后 `RemoteDisconnected`。不要作为主源。 |
| 腾讯 qfq | 只能取约 640 行。适合**做前复权交叉验证**，不适合做长窗口相关性。 |
| 快照 | `ak.fund_etf_spot_em()` 取规模（`总市值`，元）与名称。 |

> 单位自检：`amount / (volume * close) ≈ 1` 说明 amount 是元；≈ 100 则是手数口径。

## 五步流程

```
1. 抓日线  →  2. 折算校正  →  3. 相关矩阵  →  4. 分组  →  5. 组内择优代表
```

用 `scripts/dedup_pool.py` 一次跑完 2~5 步：

```bash
python scripts/dedup_pool.py \
  --dir cache3 \                 # 每个标的 <code>.csv，含 日期/收盘/成交额
  --spot etf_spot.csv \          # 全市场快照，含 代码/总市值（元）
  --out slim_out \
  --cut 0.90 \                   # 合并阈值
  --keep 510050,510300,510500,512100,563300   # 强制不合并（见「有意保留」）
```

产出 `groups.csv`（组、代表、组内平均/最小 r）、`merged.csv`、`residual.csv`、`splits.csv`。

### 聚类方式：默认必须用 complete

`--linkage complete`（默认）保证**组内最小两两 r ≥ cut**。
**不要用 single**（连通分量）：它会链式误合并——A~B、B~C 即使 A 与 C 不相关也会并成一组。
实测 109 只池子里 single linkage 会把「上证50+沪深300+创业板+深证100」和
「半导体+科创50+AI+通信+中证500+中证1000」粘成两个巨型组（20 只），结论不可用。

### `--keep` 的语义

`--keep` 里的标的**互不合并**，但**仍可被其它标的并入**。
实现上是"先聚类、再把含 ≥2 个 keep 成员的簇拆开，非 keep 成员归入相关性最高的那个 keep"。
只挡直接边是不够的——中间人会把它们重新粘连。

### 脚本不做什么

`dedup_pool.py` **只做相关性去重**。另外两件事需单独处理：

- **准入门槛筛查**（规模/成交额）：直接对快照做过滤即可，见陷阱 4；
- **复合指数检验**（线性 R²）：需自己跑回归，见陷阱 3。

顺序建议：门槛筛查 → 复合指数去冗余 → 相关性去重 → 组内择优。

## 关键陷阱（踩过，务必处理）

### 1. 份额折算会造成假跳空 —— 不处理则结论完全错误

ETF 份额折算/拆分会让**未复权价**单日"下跌" 70%~96%。若直接用未复权价算相关性，
同族标的的相关系数会被**系统性低估**（实测半导体组从 0.87~0.95 被压到 0.29~0.43），
从而得出"它们互不重复"的相反结论。

处理：`|对数日收益| > 0.25` 视为折算事件，把该日收益置 0（等效价格水平还原），
再用前复权序列交叉验证事件真实性。脚本已内置，并输出 `splits.csv`。

> 脚本扫描**全历史**，所以事件数会多于只扫分析窗口的版本（实测 31 vs 17）——
> 窗口外的折算不影响窗口内的相关性，置 0 无害。报告里宜只列窗口内的事件。

### 2. A 股宽基市值梯度的高相关是系统性的，不是重复

沪深300/上证50（r≈0.91）、中证500/中证1000（r≈0.95）、中证2000/中证1000（r≈0.93）
天然高度相关——这是 A 股同涨同跌，属于**不同市值段**而非同一暴露。
如果一刀切按 r 合并，会砍掉整个市值梯度，轮动将失去风格切换维度。
**默认放进 `--keep`，并在报告里单独披露。**

因此 `residual.csv` 里**正常会出现这些对**（如 510500-512100 r=0.953、
512100-563300 r=0.933、510300-510050 r=0.913），这不是 bug，是刻意保留。
报告里要逐条标注"刻意保留"还是"待您拍板"，并给出可选的进一步压缩方案及其代价。

### 3. 复合指数是"同一板块下注两次"

「中证科技100」「中证新能源」「上证180金融」这类宽口径行业指数，
其成分已被池内细分标的覆盖。判定方法：用池内已有标的做线性回归，`R² > 0.85` 即冗余。
（实测 515000 科技 R²=0.944。）

### 4. 文档写了准入门槛但没执行

常见问题：策略文档写了「规模 ≥ 2 亿、日均成交额 ≥ 3000 万」，
池子里却仍留着规模 0.4 亿、日均成交额 20 万的标的——信号发出后根本无法调仓。
**每次瘦身都要重新跑一遍门槛筛查，不要相信文档。**

## 组内择优规则

```
流动性分 = 0.5 × z(log 规模) + 0.5 × z(log 近20日日均成交额)
```

在最高分 **0.3 个 z 单位内** 的候选里，再选**与池内其他代表最大相关性最低**的那只。
理由：规模流动性接近时，优先消掉跨板块重复下注。

实例：半导体组三只规模相近，但 588200 科创芯片与科创50 的 r=0.951、
512480 为 0.917、159516 只有 0.831 → 选 159516。

## 报告必须包含

1. 瘦身前后 `r≥0.90` 对数占比、平均相关系数变化；
2. 合并对照表（被合并 → 并入谁 → r）；
3. 剔除清单 + 每只的剔除原因（门槛/复合指数）；
4. **残余高相关披露**：瘦身后仍 r≥0.90 的对，逐条说明"刻意保留"还是"待拍板"；
5. 数据与方法说明（窗口、样本量、已知局限、短历史新标的）。

诚实披露残余比宣称"完全消除了重复"更专业。

## 环境注意（Windows）

- 用 PowerShell 工具，不要用 Bash 工具（本机 Git Bash 的 PATH 缺失，coreutils 全部 not found）。
- PowerShell 工具**不回传 stdout**：把输出 `| Out-File x.txt -Encoding utf8` 再读文件。
- **Python 脚本报 Exit Code 1 却不生成日志文件** → 十有八九是**语法错误**
  （Python 先整体编译再执行，所以"打开日志"那行根本没跑到）。
  直接 `python -m py_compile script.py` 定位。
- **极其常见的语法错误**：在双引号字符串里用 ASCII `"` 当中文引号，例如
  `A("减少"重复下注"与噪声")`。报错形如 `SyntaxError: invalid character '、' (U+3001)`。
  改用全角 `“ ”`，或改用 `「」`。
