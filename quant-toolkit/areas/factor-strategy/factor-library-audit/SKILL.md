# FactorHub 全因子库截面审计

核心立场：**单看 |t|>2 就宣布因子有效是错的。** 一个 87 因子的库里，按纯噪声也期望有 4~5 个 |t|>2。本技能的产出价值主要来自四道闸门，而不是 IC 排名表本身。

## 先问清楚口径：全池 vs 候选集

这是动手前必须确认的第一件事，两种口径结论可能相反，**不能混用**。

| 口径 | 横截面范围 | 适用 |
|---|---|---|
| **全池口径（纯截面，默认）** | 每天对池内全部标的排序，**不施加任何策略筛选** | 用户说"我只想做截面因子分析""不要管我的策略" |
| 候选集口径 | 只在当日执行型策略实际会下单的标的内部排序 | 用户想给已有策略加截面排序模块 |

**若用户明确说只要截面分析，就交付纯全池口径**：不要出现候选集 IC 列、决策集宽度、空仓率、"执行型策略适配性"章节。这些会让人误以为"空仓"是因子分析算出来的（实测用户就会这么误解）。
实现上把候选集相关的数据字段、HTML 章节、表格列、结论条目一并剥离，明细 CSV 也应该重新生成纯截面版本，而不是沿用分析脚本里带候选集列的 CSV。

若用户的目标是执行型策略，则**两种口径都要报**（见闸门 D）。

## 何时用

- 用户有一个标的池文档（如 `ETF轮动_选股策略.md` 里的分层清单），要拿库里**全部**因子逐一测
- 用户问「我的因子库哪些能用」「帮我筛因子」「因子体检」
- 因子库有新增/改动后需要复跑
- 需要把结论做成可分享的看板

不适用：只测 1~3 个指定因子（直接写脚本即可）；判断截面因子能否适配某个执行型策略（用 `cross-section-factor-fit`）。

## 输入要件（缺一不可，缺则先问）

| 要件 | 说明 |
|---|---|
| 标的池来源 | md 文档的分层清单，或独立 txt 代码表。必须能解析出确切数量并 assert |
| 因子库 | FactorHub SQLite `factors` 表。**必须取全部 87 条，含 `is_active=0` 的停用因子**，并 assert 总数 |
| 候选集（可选但强烈建议） | 执行型策略每日实际会下手的标的，用于条件 IC。没有就只能出全池结论，且要在报告里点明这个局限 |
| 分析窗口 | 起止日期。分析起点不能早于预热后（120 日均线 + 20 日动量需 ~6 个月预热） |

## 五步流程

### 1. 加载因子库与标的池（双向 assert）

```python
# 因子：全部，含停用
db = get_db_session()
factors = FactorRepository(db).list_all()   # 不要过滤 is_active
assert len(factors) == 87, len(factors)
```

标的池用正则从 md 第四节表格解析，解析后 `assert len(universe) == 57`。
**关键：统一代码格式。** 因子面板用**6 位裸代码**（`510300`），行情源用 `sh`/`sz`+6 位。若两处格式不统一，候选集 IC 会**静默全空**（不报错，只是没结果）——这是本流程最容易踩的坑。

### 2. 行情拉取 + 份额折算校正（ETF 必做）

新浪 ETF 日线**未复权**，基金份额折算/拆分会造成 |对数收益| > 25% 的假跳空，直接算 IC 会被污染。

区分两类，处置方式不同：

| 类型 | 特征 | 处置 |
|---|---|---|
| 单日毛刺 | 次日反向复原 | 抹平为前日价（不改量） |
| 水平位移 | 份额折算，价格跳台阶后不回来 | 按比例**后向复权**价格 + **反向缩放**成交量 |

漏做或做错方向，都会让动量类因子凭空变强或变弱。记录全部事件供报告披露。

### 3. 因子计算（走 FactorHub 引擎，不要自己重写公式）

用 `factor_service.calculator.calculate`，不要在外面用 pandas 重实现——否则「库里那个因子」和你测的因子不是同一个东西，结论无法回填到库里。

缓存 `panel.pkl`，统计**失败单元数必须为 0**。

### 4. 四道闸门（本技能的核心）

#### 闸门 A — 多重检验校正
- Bonferroni：α=0.05、n=87 → 门槛 **|t| ≥ 3.44**
- Benjamini-Hochberg FDR：算 q 值（用 `math.erfc` 实现正态尾概率，不依赖 scipy）
- **必须同时报**「名义显著 |t|≥2 的个数」和「过校正后的个数」。前者通常 19 个左右，后者常常是 **0**

#### 闸门 B — 去冗余独立效应
87 个因子里大量是同一逻辑的变体。逐对算相关性：
- `|r| ≥ 0.95` 的配对数（实测可达 79 对）
- 把 |t|≥2 的因子按高相关簇聚类，报「**去冗余后独立效应数**」——19 个名义显著常常只剩 8 个

只报名义数量 = 严重夸大。

#### 闸门 C — 前视偏差检测
取 3~4 只有代表性的标的，把数据**截断到某个历史日**（如 2025-06-30）重算因子，与全量算出的同一日历史值比对：
- 相对偏差 < 1e-6 → 通过
- 标记「经过未来数据的归一化/排名/z-score」的因子
- 遗传挖掘类（`Mined_Factor_*`）是重点嫌疑

#### 闸门 D — 候选集条件 IC
执行型策略的入场信号本身就是一个筛选器。走到决策集的标的在动量维度**已经在高分位**，此时全池 IC 会给出**方向相反的乐观结论**。

**必须只在当日候选集内部算 IC**（要求 n≥3）。这是 `cross-section-factor-fit` 的第一铁律，此处复用。

同时报**决策集宽度**：候选数中位数、≤2 只的交易日占比、空仓天数。若中位数 ≤2 或 ≤2 的占比 >50%，说明**排序在统计上不成立**，应转向资金分配问题，而不是继续找因子。

### 5. 看板 + 部署

自包含响应式浅色 HTML（无外部依赖），必备 8 个区块：
核心结论 / KPI / 执行型适配性检视 / 分类条形 / IC 分布 / 散点 / 决策集宽度 / 87 因子排名表（可搜索筛选排序详情）/ 因子冗余表 / 数据与方法

部署走 `deploy-node-aliyun-light` 的路子：上传到 `/var/www/<slug>/`，nginx 幂等插入 location，`nginx -t` 通过才 reload，失败回滚。

## 结论写法（最容易翻车的地方）

写看板结论前，**逐条回查原始数字**。已知的翻车案例：初稿写「3 个因子通过 Bonferroni」，核实后发现最小 BH-q=0.0624>0.05、最大 |t|=3.38<3.44 → 实际是**没有任何因子通过校正**。

### 周期方向上有个反直觉陷阱（实测踩过）

**不要想当然地说「|IC| 随周期拉长而衰减」。** 实测某池 87 因子：

| 周期 | 平均 \|IC\| | \|t\|≥2 的因子数 |
|---|---|---|
| 1 日 | 0.0113 | **17** |
| 5 日 | 0.0108 | 1 |
| 10 日 | 0.0146 | 2 |
| 20 日 | **0.0209** | 2 |

平均 |IC| 是**上升**的，塌陷的是 |t|≥2 的**个数**。机制：1 日周期有约 750 个近似独立观测，t 值容易做大；拉长周期后重叠收益使有效样本缩水、IC 序列自相关增强，|IC| 更大却撑不起 |t|。
所以叙述要写成「名义显著集中在短周期 / 长周期的 |IC| 更大但撑不起 t」，而不是「信号随周期衰减」。**两个量先各自算出来再下结论。**

必须披露的反面事实：
- 名义 |t|≥2 的因子数 vs 纯噪声期望数（87 因子下约 4~5 个）
- 最强因子若是**停用因子**，要检查其实际公式是否与描述相符（实测有描述与公式不符的情况，不能直接采用）
- 标的池的有效独立赌注数 `N_eff = (Σλ)²/Σλ²`（participation ratio）。若 N_eff/名义只数 < 20%，说明池子高度冗余，IC 的置信区间比看起来宽

## 环境坑（本机实测）

- **Bash 工具不可用**（缺 dirname/ls），一律走 PowerShell
- **PowerShell 的 stdout 不回显**：命令结果要 `Set-Content` 到文件再用 Read 读
- **`Remove-Item` 被安全守卫拦截**：报 `SAFE_DELETE_FAIL_CLOSED` / trash 失败，但**文件其实已删掉**，报错是假阴性，别重试
- **`Invoke-WebRequest` 的 `$r.Content` 是 byte[]**：`[string]$r.Content` 会得到 `System.Byte[]`，内容检索全部失效。先判断类型再用 `[Text.Encoding]::UTF8.GetString()`
- **看板字节数对不上别慌**：Python `len(html)` 是**字符数**，磁盘/线上是**字节数**（中文 UTF-8 占 3 字节），以 MD5 为准
- 项目依赖（numpy/pandas）在 `FactorHub/.venv`；**上传用的 paramiko 在 default 环境**（`C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`），项目 .venv 没有 paramiko
- SSH 上传：`~/.workbuddy/skills/deploy-node-aliyun-light/scripts/ssh-run.py`，私钥 `C:/Users/Administrator/Desktop/workbuddy.pem`
- akshare 新浪 A 股日线接口常挂，ETF 用 `fund_etf_hist_sina`；东财接口受代理拦截，不要依赖
- 校验 HTML 内联 `<script>` 用 node 的 `vm.Script`，提取内嵌数据时 regex 要容忍 `\r\n`
