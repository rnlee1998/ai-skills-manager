# 量化策略回测归因诊断

## 何时用

用户拿到一份回测结果（收益、逐标的盈亏表、日志），想判断：
- 亏损/盈利来自哪一层（池子？信号？仓位？）
- "优化某条件""动态调池"能不能改善
- "有的标的赚钱了，事先怎么筛出来"

## 铁律：先补基准对照，再谈任何优化

**没有同池等权买入持有的基准，任何回测结论都无效。** 三步对照：

| 对照 | 算法 | 回答 |
|---|---|---|
| 全池等权满仓 | 池内标的区间收益的等权平均 | 池子本身有没有收益 |
| 同仓位对照 | 上者 × 策略平均仓位 | 剔除仓位差异后的公平基准 |
| 策略实际 | 账户末值 | 信号层贡献 = 实际 − 同仓位对照 |

第二步极易被忽略：若策略平均仓位只有 1/3，直接拿它跟满仓基准比会得出错误结论。

## 四项检验

### 0) 数据口径自检（最先做，做错会让长周期结论整体反转）
在算任何累积收益之前，先确认收益矩阵里装的是**简单收益还是对数收益**：

```
抽一天原始涨跌超过 ±5% 的样本（或一段价格比）：
  若 矩阵值 ≈ ln(1 + pct_change)  →  是对数收益
  还原价格指数必须用  np.exp(r.fillna(0).cumsum())
  用 (1+r).cumprod() 会系统性低估长周期涨幅（每 1000 个交易日约吞掉 11~15pp）
```

**为什么致命**：低估幅度与**波动率平方 × 天数**成正比，所以**基准（长期满仓）被低估得比策略（短持仓、有现金）更狠**，
结果就是凭空得出"策略跑赢基准"的假象。验收办法：还原后的指数必须与原始收盘**比值完全相等**
（例：某标的原始收盘 +16.14%，引擎指数也必须是 +16.14%），差 1pp 以上就是口径没对齐。

另外两项同样要自检：**复权口径**（未复权序列会漏掉分红，长窗口可比性下降）、
**份额折算**（见"坑"第一条，必须先校正再算收益）。

### 1) 仓位核算（先做，否则后续全错）
从日志解析每次账户打印的 `持仓市值 / 总资产`，取平均。同时核对逐标的盈亏合计与账户 `累计已实现` 是否一致。
注意：脚本里"每只预算 = 初始资金 / 当日池只数"和"资金均匀分给 N 只"完全不是一回事——只有出信号的才买，多数资金闲置。

### 2) 信号前瞻预测力（核心）
对每一个 (标的, 交易日) 观测，算 h ∈ {3,5,10,20,40} 日的前向收益，比较：

```
信号子样本均值  vs  非信号子样本均值   →  t 检验
```

- 用**互斥子样本**（信号 vs 非信号），不要用"信号 vs 含信号的全体"（会把差值稀释一半）
- 逐持有期做，得到**信号半衰期**：优势在第几天消失
- **关键检查：信号半衰期 vs 实际平均持仓周期**。半衰期 3~10 日而持仓 21~26 日 = 严重错配，优势赚完又还回去
- 若信号之上还有"买点门"之类的二次过滤，**做消融**：信号-only vs 信号+门，看门是加分还是抹掉优势

### 3) 分池/筛选规则的前瞻检验
把策略的分类规则（如按波动率分 A/B/C）在每一天复算，比较各类别的 h 日前向收益 + t 检验。
若 A 类显著跑输 C 类而策略只交易 A+B，则分类方向是反的——这比"调整阈值"重要得多。

### 4) "事先能不能筛出赢家"——识别事后选择偏差
用户看到"有些标的赚钱了"时的三个反证：

- **反证 1**：检查赚钱榜里有没有标的自身区间是下跌的。若有 → "赚钱"是 (标的 × 进出时机) 的联合产物，不是标的属性，"只做多这些标的"这个前提不成立
- **反证 2**：把区间对半切，看赢家的利润来自前半段还是后半段。若全在前半段 → 期末的赚钱榜记录的是行情，不是能力
- **反证 3（决定性）**：取时点 T，**只用 T 之前可得的信息**排序，看 T 之后表现：
  ```
  score = 近60/120日收益、250日波动率、策略自身的分类标签 …
  j = concat(score, forward_return).sort_values(score)
  Top10 / Bottom10 / 全体 的 forward_return + Spearman rho
  ```
  再算**随机抽同样只数 2 万次的分布**（均值、标准差、5%/95% 分位），看 Top10 落在随机分布的第几个标准差外。
  **多点重复**（换若干个 T），不要只在一个时点做。

同时算**跨期横截面 Spearman**（把区间切成 3 段，两两算）：接近 0 = 无动量、无法筛；显著为正 = 动量可用；显著为负 = 反转（此时"按动量筛"是反向指标）。

## 输出格式

- 先给"策略 vs 同池等权"的一句话结论
- 再给 3~4 张图：信号前瞻（分持有期）、分池前瞻、期中筛选实验（含随机区间带）、赢家前后段分解
- 图里正收益用红色、负收益用绿色（A 股习惯）
- 最后给按性价比排序的下一步：**消融实验 > 拉长样本 > 补基准 > 动池子**

## 坑

- **折算/拆分**：原始价会出现 -70%~-96% 的假日收益，必须校正（|对数日收益| > 25% 置 0），否则相关性/收益全错
- **截图与日志对不上**：先用 `累计交易量`（= 各轮买入份数之和）或逐标的盈亏去精确匹配是哪一次回测，再分析。持仓天数口径各平台不同，不要用它匹配
- **脚本编码**：QMT 策略常写 `# coding:gbk` 但文件实为 UTF-8；改这类文件要用字节级替换并保持换行符，别让编辑器重写
- **只读数组**：pandas 3.x 的 `.values` 只读，用 `.to_numpy(dtype=float).copy()`
- **样本量**：一百多个交易日的单一区间只能算一次试验，不能外推；结论要写明"单一区间、单一市场状态"
- 分红未复权对 20 日以内窗口影响可忽略，长窗口需说明
- **收益矩阵是简单收益还是对数收益**：见第 0 步。这是最容易埋雷、影响最大的一条
- **`DataFrame & Series`（布尔运算）在 pandas 中按【列】对齐**，不是按行。
  用它做时间掩码会静默造出畸形宽表（109 列 + 5240 行 → 5349 列），报错信息很隐晦。
  布尔掩码一律先 `.to_numpy(dtype=bool)`，再用 `B & mask[:, None]` 做行掩码
- **明细表常含"代表 + 被并入"两种角色**：取池子前必须过滤 `角色=="代表"`，否则池子被悄悄放大（如 57 → 81）
- **止损/退出的机会成本要按"规则是否重新入场"来算**：单看"止损后标的涨回来了"会得出"止损有害"的错误结论。
  正确做法是统计**亏损退出后有百分之多少在 N 天内被规则重新买入、那一笔的结果如何**，
  以及**止损 vs 硬扛到 +20/40/60 日**的反事实对比（后者衡量"用收益换回撤"的代价，不是判据）
- **长历史行情来源**：baostock 可能只返回近期窗口（实测 `start_date=2021-06-01` 只回 163 根，且 513xxx 之类代码后缀写错会直接返回空）。要拿多年面板改用新浪 K 线
  `http://money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData?symbol=sh510300&scale=240&ma=no&datalen=1500`
  返回 1500 根日线（最早约 6 年前）。坑：**keys 无引号**，需先 `re.sub(r'([{,])\s*([A-Za-z_]\w*)\s*:', r'\1"\2":', raw)` 再 `json.loads`；**不复权**（高分红标的会引入 1~3% 假下跌，需在局限里写明）；**无 amount 字段**，用 `volume × close` 近似成交额。
- **PowerShell 工具会把 stderr 的 RuntimeWarning 当 NativeCommandError**：脚本实际成功也会返回 exit code 1。
  判断成败要看**输出文件是否生成**，不要只看 exit code。
- **市值/权重类脚本易踩的下标错**：核对池子代码后缀（513xxx/51xxxx/56xxxx/58xxxx 属沪市，159xxx 属深市）。后缀写错时数据源返回空，标的会被**静默跳过**，导致"N 只池实际只跑 N-1 只"且仍计入分母。
