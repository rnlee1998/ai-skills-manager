# MA20 策略回测日志分析

## 这个技能解决什么问题

用户会反复跑不同因子组合（combo1 ~ combo11）的回测，每次产出若干份
`csi1000_backtest_log_YYYYMMDD_HHMMSS.txt`（每份约 0.5MB / 5000+ 行），
然后要求「分析这个交易日记」。本技能把「日志 → 可交付分析」这条链路固定下来，
避免每次重新踩解析坑。

标准分析窗口：**2020-01-02 ~ 2023-12-29**（970 个交易日），初始资金 1000 万。
每份日志 = 一个因子组合，因子定义只有在 combo2+ 的头部行才打印。

---

| `[仓位已满]` | `[20200107] [仓位已满] 持仓10只达上限10, 不买入` | ~300 |

### 1.1 ★ 策略口径速查（分析前必须知道，否则会得出错误结论）

| 项 | 事实 | 对分析的影响 |
|---|---|---|
| **因子得分** | **不是原始因子值，是「A 池内分位数」**。分母 = `A池只数-1`（实测 1/52 网格 ↔ 日志 `A类53只`） | 截面 IC 是全市场/1000 只口径，这里是 53 只口径 → **两者符号无理由一致** |
| **A 池** | `idx_corr_20` 排名前 200 **且 corr>0.5** 且总市值最小 200；实际只有 **12~63 只** | 池子极小 → 任一分位排序都在 40~50 只里挑 10 只，区分度被同质性吃掉 |
| **持仓天数** | 8% 档中位 **28 天**（2352 笔）；15% 档中位 **100 天**；顶背离中位 **136 天**（54 笔，最长 428 天） | 1 日型信号（如量比）的 1~5 日 IC **不该**外推到 28~136 天的持仓 |
| **利润来源** | 三档中**只有顶背离档赚钱**，且 8% 档与 15% 档的表现在各因子组间几乎相同 | 因子只在「能否走到顶背离」这一个通道上起作用（见 §5.3） |
| **量比 vs 换手** | 换手 = 20日均量/总股本（**水平量**，横截面有意义）；量比 = 当日量/自己的20日均量（**时序比值**，自归一化已除掉水平信息） | 两者选股重合仅 **35.4%**，**不是同一族因子**，`-换手` 有效推不出 `-量比` 有效 |
| **择时** | 开关 ON 仅 **40.6%** 的天数，OFF 期**只禁买不清仓** | 系统性暴露只有目标的 ~76%（平均持仓 7.6/10 只） |

**因子定义以日志头部 `因子组合comboN` 行的菜单为准**，但注意 ⚠️：
**菜单文字会随参数改动而变，历史日志里的菜单可能对应的是「当时」的设置。**
实测 c2/c3 头部写 `4=+量比`、c4 起写 `4=-量比` —— 说明符号在 c3→c4 之间被改过，
而 **c2/c3 实际跑的是 combo2/combo3，`+量比` 从未被真正回测**。
⇒ **判断某方向有没有测过，要同时看菜单 + `因子得分(comboN)` 行 + 当日候选得分特征，
三者都指向同一个 combo 才算数。**

## 二、★ 两个必踩的解析坑（不处理会静默出错）

### 坑 1：股票名称含空格
`000025.SZ 特 力Ａ`、`002215.SZ 诺 普 信`、`002181.SZ 粤 传 媒` —— 用
`(\S+) (\S+)` 匹配「代码 名称」会在名称空格处断掉，**静默漏掉约 6 笔卖出/买入**。
✅ 正确写法：`(\d{6}\.[A-Z]{2})\s+(.+?)\s+(\d+)份`（非贪婪 + 以 `N份` 为锚点）

### 坑 2：`[买入]` 有两种行
预算行 `[买入] 可用资金… -> 每只预算…` **不是成交**，必须先剔除，
否则「买入笔数」会虚高（combo1 有 78 条预算行）。
✅ 正确写法：成交行必须以 `代码 名称 N份 成交价` 开头。

### 坑 3：卖出原因在第 8 个捕获组
正则 `^\[(\d{8})\] \[卖出\] ... \((.*)\)$` 里 group(8) 才是原因，
误用 group(7)（佣金）会导致浮盈全部解析为 None，进而 `ZeroDivisionError`。

### 坑 4：`%+,.0f` 不是合法的 %-格式化
Python 的 `%` 格式化不支持逗号千分位，必须写 `format(x, '+,.0f')`。

## 三、★ 强制自检：配对结果必须等于日志自报的「累计已实现」

解析完必须做这个校验，通过才说明配对算法正确：

```
sum( (卖出金额 - 买入金额 - 双边佣金) for 配对笔 )  ≈  日志最后一条「累计已实现」
```

实测四组误差 2~31 元（10 万级以下）。若误差是百万级 → 配对或金额解析错了。

配对方法：同代码 FIFO（买入队列 pop(0) 去匹配卖出）。

## 四、必出的六个分析维度

### 1. 卖出规则盈亏归因（最有价值）
按触发原因分组统计「笔数 / 合计盈亏 / 平均浮盈 / 胜率」。三条规则：
- `回撤8%档+破MA5`（浮盈<10% 时启用）—— 实测占 87~91% 的交易
- `回撤15%档+破MA5`（10%≤浮盈<30% 时启用）
- `MACD顶背离清仓`（浮盈≥70% 时启用）

判据：`回撤(\d+)%>(\d+)%` 取阈值；含 `顶背离` 归第三类。

> **这是全篇最重要的输出。** MA20 策略的典型画像：8% 档扛下全部亏损，
> 顶背离只触发 4~7 次却贡献了净利主体。改动卖出规则是投入产出比最高的优化点。
> 注意「15% 档 100% 胜率」是规则设计使然（只在浮盈≥10% 才启用），不是预测力证据。

### 2. 收益集中度（尾部依赖）
按单笔盈亏排序，算「剔除盈利最大 1/3/5/10/20 笔后的累计盈亏」。
若剔除 Top3 就转负 → 策略收益高度依赖少数大赢家，需说明其脆弱性。
同时列出各组合的 Top5 盈利标的，**看跨组合重复出现的票**——重复出现的说明
选股力来自共用环节（A池分池 + MACD择时），而非因子本身。

### 3. 择时开关效率
`开关ON` 占比（典型 40.6%，各年 37~47%）、分年度 ON 占比、分年度平均持仓只数。
**注意 ADX14 只被打印、未参与开关条件**：实测 ON 时 ADX 中位 56.2、OFF 时 61.2，
两者不可分 → 是无效展示字段，可以建议删掉或真正接入。

### 4. 仓位利用
平均持仓只数（典型 7.6/10）、空仓/≤2只/≥8只天数。
不满仓的原因：OFF 禁买（59% 时间）+ 卖出快于买入 → 系统性暴露只有目标的约 76%。

### 5. 交易成本
换手率 = (买入额+卖出额)/初始资金（典型 4800~5700%）。
摩擦 = 佣金(0.03%) + 滑点(双边各 0.1%)。**滑点约为佣金的 3.3 倍**，
是大头，报告时务必分开列。

### 6. ★ 因子边际贡献 / 分档归因（用户问「因子符号对不对」时必做）
两个动作，缺一不可：
1. **按退出规则 × 因子组做分档盈亏**，并按组内 combo 数归一化。
   实测结论：8% 档与 15% 档在 5 个因子组间几乎相同，**全部差异集中在顶背离档**。
2. **统计各因子的「大赢家笔数」**（>50% / >100%），而不只看平均收益率 ——
   利润集中在少数长持仓交易上，均值会被稀释，笔数才暴露真相。

工具：`scripts/analyze_factor_marginal.py`（见 §5.3）。锚点见 §7.3。

## 五、脚本用法

### 5.1 基础分析：`analyze_ma20_log.py`

```bash
<python> scripts/analyze_ma20_log.py "<日志目录>" "<combo1文件,combo2文件,...>" "<c1:因子,c2:因子,...>"
# 例：
<python> scripts/analyze_ma20_log.py "D:\WorkSpace\Myrepo\quant\MA20 stratedgy" \
  "csi1000_backtest_log_20260923_163146.txt,csi1000_backtest_log_20260923_165509.txt"
```

输出 `<目录>/_ma20_analysis.txt`（人读报告）+ `_ma20_analysis.json`（结构化）。
可复用函数：`parse()` / `pair_fifo()` / `m0()` / `c0()` / `kind_of()` / `INIT` / `analyse()` / `render()`。

### 5.2 ★ 选股归因：`analyze_selection_overlap.py`

**当用户问「这些因子是真的改变了选股吗」「收益是不是靠吃到大票」「哪个组合更好」时用这个。**
它把「11 个因子组合 = 11 个独立下注」这个默认假设直接证伪。

```bash
<python> scripts/analyze_selection_overlap.py "<日志目录>" "<a.txt,b.txt,...>" ["标签1,标签2,..."]
```

输出 `<目录>/_selection_overlap.txt`，共 6 节：

| 节 | 内容 | 一句话读法 |
|---|---|---|
| 【1】 | 逐日选股重合度矩阵（`\|A∩B\|/max(\|A\|,\|B\|)`） | 平均重合 ~48%、随机基准 20% → 因子非全无信息但远非互斥 |
| 【2】 | 重合度 ≥60% 单链聚类 → **有效独立策略数** | 11 个组实际只有 5 类；类内极差可达 21pp |
| 【3】 | 各组 Top10 赢家重合度 + 「收益率完全相同」占比 | 相同收益率 = 同一笔交易 → 因子零贡献 |
| 【4】 | 分年度收益 + 年度间 Spearman 秩相关 | 秩相关 ≈0 → 「今年谁赢」基本重新抽签 |
| 【5】 | 反事实：去最好 1/3/5 笔后的盈亏 | 去 Top3/Top5 后普遍转负 → 收益由极少数交易决定 |

**实现要点（改脚本前必读）**：`[买入候选]` 每行有**两种**形式 ——
说明行 `按因子得分取前N只, 其余M只未入选` 与**明细行** `代码(市值X.X亿 得分Y.YYY)`。
**只有明细行枚举了真正买入的标的**，必须用 `"(市值" in 行内容` 过滤掉说明行，
否则会把「未入选」的票也算进选股集合。依赖同目录的 `analyze_ma20_log.py`（importlib 复用）。

Bash 工具在本机不可用，一律用 PowerShell 调用 managed python，
输出落文件后再用 Read 读取（PowerShell stdout 不回显）。

### 5.3 ★★ 因子边际贡献 / 符号方向诊断：`analyze_factor_marginal.py`

**当用户问「截面检验说这个因子有效，为什么回测里相反」「因子符号是不是搞反了」
「因子怎么组合」时用这个。** 它把「按退出规则分档」和「因子的边际贡献」接起来。

```bash
<python> scripts/analyze_factor_marginal.py "<日志目录>" "<a.txt,b.txt,...>" "<标签1,标签2,...>"
```

输出 `<目录>/_factor_marginal.txt`，7 节。**两个必须照抄的设计（否则结论会错）：**

1. **只用「同口径建仓日」做横截面对比。** 判据：当日有 ≥8 个组合各买入 ≥6 只
   （脚本自动筛，实测 11 天）。**理由**：实测 74~80% 的买入日是「只买 1 只」，
   谁有空位是**路径依赖**的 → 全样本下「共识度」会被「当日有几组恰好有空位」污染，
   不能当作纯因子共识。
2. **分档盈亏必须按「组内 combo 数」归一化。** 各因子组包含的 combo 数不同
   （`-ATR` 有 6 个、`-换手` 只有 2 个），不归一化会把组合数当成因子效应。

**核心输出（这是判断「因子到底在哪一档起作用」的关键）**：三档退出规则的盈亏，
按因子组归一化后，**8% 档与 15% 档在 5 个因子组间几乎完全相同**
（组间极差仅 170 万 / 189 万），**全部收益差异集中在顶背离档**（极差 638 万，3.1 倍）。
⇒ 在这套框架里因子不预测收益，只决定「能不能持有到浮盈≥70% 的顶背离」。

**两个容易写错的实现点**：
- 共识度要按 `(code, buy_date)` 归并，且计数的是**有多少个 combo**，
  不是有多少个不同的收益率值（写错会得到一个看似合理但完全错误的数）。
- 大赢家统计（>50% / >100% 笔数）比「平均收益率」更能暴露因子的真实作用 ——
  策略利润集中在少数长持仓交易上，均值会被稀释。

**⚠️ 方法论强制项（本轮靠它拦下一个错误结论）**：
池化统计**必须**做逐日稳健性检验。本轮「低共识更好」的池化形态看似单调，
但逐日看 9 天里只有 4 天成立、差值在 −8.6%~+15.9% 间乱翻 → **结论不成立，已移除**。
**没有逐日检验的分层结论，一律不许写成结论。**

**因子归属怎么定**（用户不一定说清哪份日志是哪个 combo）：
1. 先看头部 `因子组合comboN:` 行
2. combo1 的头部缺这行 → 用**首日买入候选的得分特征**反推：
   - 得分全部 ≤0 → 负向因子（`-ATR` / `-量比`）
   - 得分全正且与市值严格同序 → `+市值`
   - 得分全正但市值乱序 → `+反转`
3. 拿不准就问用户，别猜。

### 5.4 ★★ 止损反事实检验：`analyze_stop_counterfactual.py`

**当用户问「止损是不是亏太多」「不止损会怎样」「要不要放宽止损」时用这个。**
它回答的是「被止损的交易如果不止损会怎样」——这是 `kinds` 分档表回答不了的。

```bash
<python> scripts/analyze_stop_counterfactual.py "<日志目录>" "<全部文件,含v21>" "<v19文件子集>"
```

输出 `<目录>/_stop_counterfactual.txt`。**设计要点（照抄，别自作主张改）：**

1. **价格地图来自持仓明细块**：每份日志的持仓表每天打印每只持仓股的「现价」，
   跨日志交叉拼出 `code -> {date: px}`（16 份日志 ≈ 546 标的 / 8,763 价格点）。
   买卖成交价也要并入地图。
2. **事件只用 v19 引擎的日志**（卖出规则一致）；v21 日志只用来**供价格**，不产事件。
3. 三种处置模拟（B1 放宽12% / C 持有+20日 / D 持有+60日）必须附
   **「剔除离群标的」敏感性**（D′）：本轮 D 的 +16.3% 里永兴材料 ×5 笔占 68%，
   剔除 002756/000913 后只剩 +0.85% ≈ 0。**不做 D′ 就会把尾部运气当成止损线的缺陷。**
4. 必须报告**覆盖率**（仅 13~17%，价格只在其他组合仍持仓时可得）并声明偏差方向。

**11 组锚点（c1~c11, 2,352 笔事件）**：+5/+10/+20/+60 日反事实中位
+2.32% / +3.60% / +1.15% / **−2.56%**（+60日仅 37.1% 高于止损价）；
B1 = −7.2%，D = +16.3%，D′ = +0.85%；「仍浮盈被止损」的 652 笔 +60日中位 −4.82%。
⇒ 正确结论：**8% 止损本身不亏（中位口径），放宽更差；可收割的是 5~10 日的超卖反弹
（止损卖在了短线最弱的 K 线上）→ 建议变体「触发后等反弹日卖出 + 12% 硬兜底」。**

### 5.5 ★★ 止损阈值的噪声尺度标定：`analyze_stop_volscaling.py`

**当用户问「阈值为什么是这个数」「止损怎么定才不是过拟合」「12%/8% 的理由」时用这个。**
它回答「阈值该由什么决定」——答案是 σ（噪声尺度），不是回测收益。

```bash
<python> scripts/analyze_stop_volscaling.py "<日志目录>" "<全部文件,含v21>" "<v19子集>"
```

输出 `<目录>/_stop_volscaling.txt`，五节。**方法论要点（这是本脚本存在的意义，照抄）：**

1. **k 不从 P&L 挑**：k\* 从漂移0随机游走 MC 的「纯噪声触发率曲线」上按目标误触发率
   （20%，显式的风险偏好）读出。P&L 只出现在验证环节。
2. **必须先做机制检验**（§2）：按 σ 四分位分层看止损后走势，可证伪预测是

## 八、环境注意事项（本机实测）

- **Bash 工具不可用**（`mkdir`/`cd`/`dirname` 全报 command not found）→ 一律 PowerShell。

  同样被拒）→ **但「删到回收站」仍有解**：用 Python `ctypes` 直接调
  `shell32.SHFileOperationW`（`wFunc=FO_DELETE`、`fFlags` 含 `FOF_ALLOWUNDO=0x40`），
  纯标准库、不碰 Add-Type。完整片段见跨项目记忆 `~/.workbuddy/MEMORY.md`
  「本机安全策略拦截项」一节。**动手前先读那一节，别重复试错。**
  兜底方案：`Move-Item` 归档到 `$env:TEMP\<name>_scratch_archive_<date>\`（可逆，已验证）。
- **技能挂载已实证同步**：三个应用侧 skills 目录**本身就是 Junction** →
  `D:\WorkSpace\Myrepo\ai-skills`（根级挂载，各 35 个子项相同）。
  写 `D:\WorkSpace\Myrepo\ai-skills\<skill>\` 后，
  `C:\Users\Administrator\.workbuddy\skills\<skill>\` 立即可见同一份文件。
  ⚠️ 子目录的 `.LinkType` 恒为空、`.Target` 报的是**不存在的** `C:\WorkSpace\...`（僵尸字段），
  **判合规只能靠「写入后从应用侧读回」**，别信这两个字段。
- **临时文件别留在项目目录**：分析完把**自己临时写的** `_*.py` / `_*.txt` / `_*.json`
  归档走，只留最终交付物（如 `交易日记分析_YYYYMMDD.md`）。

  `_selection_overlap.txt`）按设计就写在日志目录，**保留即可**，它们是结论的证据链。
