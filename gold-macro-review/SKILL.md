# 黄金宏观指标复盘看盘

## 概述

对黄金价格走势产生核心影响的6项宏观指标进行系统性复盘，生成包含数据、多空标注、逻辑说明和综合判断的HTML看盘网页。为节省 token，**默认不重复抓取数据**：若当日报告已生成，则主动询问用户是「直接查看已生成报告」还是「更新分析（重新抓取最新数据）」，默认推荐直接查看（见"步骤-1"）。仅在用户明确要求刷新、或选择「更新分析」时，才重新获取数据并生成。

## 触发条件

当用户提出以下请求时触发：
- "黄金行情"、"黄金看盘"、"黄金复盘"、"黄金宏观分析"
- "金价指标分析"、"黄金多空判断"
- "帮我看一下黄金"、"黄金现在什么情况"
- 任何涉及黄金宏观面、金价驱动因素分析的需求

## 固定分析指标（6项）

| 序号 | 指标 | 数据来源 | 核心关注点 |
|------|------|----------|-----------|
| 1 | 美国10年期TIPS实际收益率 | 同花顺黄金数据中心 `real_yield` | 实际利率水平与趋势，是否与金价负相关关系失效 |
| 2 | 美元指数 DXY | WebSearch（Yahoo Finance / TradingView） | DXY水平、趋势、是否创阶段性新低 |
| 3 | CME利率期货/美联储货币政策预期 | 同花顺 `fed_interest_rate` + `cme_position` | 下次FOMC维持/加息概率、CME多空持仓变化 |
| 4 | 美债拍卖/财政部债务操作/财政风险 | WebSearch（Reuters / 新闻源） | 长债拍卖收益率、投标倍数、联邦债务规模、回购操作 |
| 5 | SPDR黄金ETF持仓变化 | WebSearch（24k99.com等）+ 同花顺 `etf_capital` | GLD持仓吨数、日/周/月变化、中国ETF资金流向 |
| 6 | WGC全球央行净购金 | 同花顺 `global_gold_reserve` + `cn_gold_reserve` + WebSearch | 季度净购金量、中国央行月度增持、全球储备总量 |

## 工作流程

### 步骤-1：当日报告去重 + 主动询问（必须最先执行，默认省 token）

用当天日期（北京时间，记为 $TODAY）检查工作目录中是否已存在当日报告：

```bash
ls -lt <工作目录>/gold_dashboard_$TODAY.html
```

并读取同日元数据文件 `<工作目录>/gold_dashboard_$TODAY.meta.json`（结构见"步骤6"，用于提示时效性）。

判定规则：
- 任一黄金看盘报告 HTML 的修改时间为今天 → 视为"今日报告已生成"。

分支处理：

**A. 不存在今日报告** → 直接执行完整流程（步骤0→步骤6），无需询问。

**B. 已存在今日报告 + 用户显式要求"刷新/重生成/更新数据/强制更新/更新分析"** → 跳过询问，直接执行完整流程（强制刷新）。

**C. 已存在今日报告 + 用户未显式要求刷新（默认场景）** → **默认不重新抓取数据，先主动询问用户**：

1. 若 meta.json 存在且含 `pending_events[]`，计算其中 `release_at`（北京时间）≤ 当前时间 且 `released` 为 false 的条目，作为"自上次生成后已释放的重大事件"列表（用于提示用户时效性）。
2. 使用 `AskUserQuestion` 工具向用户提问（一次即可），问题形如：
   - **问题**：「今日黄金分析报告已于 {HH:MM} 生成（含6项宏观指标）。是否要基于最新数据重新分析？」
   - **选项1（推荐）**：「直接查看已生成报告」——直接 `present_files` 推送已有 HTML 并结束，不消耗额外 token。若 meta 中有已释放事件，可在选项描述中补充「注：自生成后已有 {事件名} 公布，原报告可能未完全反映该数据」。
   - **选项2**：「更新分析（重新抓取数据）」——执行完整流程（步骤0→步骤6），并在"步骤2.5"纳入已释放事件的实际数据。
3. 根据用户选择：
   - 选「直接查看」→ 推送已有 HTML，回复注明「今日报告已于 HH:MM 生成，按您选择直接展示，未重复生成」，结束流程。
   - 选「更新分析」→ 执行完整流程。
4. 若任务要求发送邮件：选「直接查看」则发送已有报告；选「更新分析」则生成后发送。

> 设计目的：在"省 token（不重复抓取）"与"数据时效（盘中重大数据公布后可刷新）"之间平衡。**默认推荐直接查看已生成报告**；当用户认为有必要时（如盘中重大数据已公布）可自行选择更新。删除旧的"STALE 自动强制重算"逻辑——改为由用户决策是否需要刷新。

### 步骤0：获取三地金价数据（页面顶部展示）

**（a）国内金价（SGE 现货）**：

```bash
curl -s --max-time 15 "https://hq.sinajs.cn/list=SGE_AU9999,SGE_AUTD" -H "User-Agent: Mozilla/5.0" -H "Referer: https://finance.sina.com.cn/" | iconv -f gbk -t utf-8
```

**（b）同花顺实时行情**：加载 `ths-gold-market-quote` 技能，运行 `python scripts/query.py --symbol london-gold --symbol au9999 --symbol autd` 获取最新分时价（周末/休市时部分品种可能不返回，需用（a）（b）和新闻源兜底）。

**（c）交叉验证**：WebSearch 搜索 "AU9999 收盘 元/克" 等确认国内金价口径（收盘价 vs 夜盘价需区分标注）。COMEX 12月合约价格（新闻源）与新浪 GC 主力连续价格可能略有差异，同时展示并注明合约。

### 步骤1：获取同花顺黄金数据中心数据

加载 `ths-gold-center-market-data` 技能，运行以下指标查询：

```bash
python scripts/query.py --metric real_yield --metric fed_interest_rate --metric cme_position --metric etf_capital --market cn --before 10 --metric global_gold_reserve --metric cn_gold_reserve --metric term_spread --metric fear_index
```

提取每项指标的最新值、前值、数据点数。注意：
- `real_yield` 读取 `metrics[0].metrics_data` 中的 `time[]` 和 `value[]`，第一个元素为最新
- `fed_interest_rate` 读取 `list[]`，按 `meeting_date` 分组，`items[]` 中 `rate_range` 和 `probability` 为关键字段
- `cme_position` 读取 `cmeLong`、`cmeShort`、`cmeLongShortRatio` 三个 metrics
- `etf_capital` 读取 `indic_data`（日度数据）和 `interval_data`（区间累计）
- `global_gold_reserve` / `cn_gold_reserve` 读取 `time_range[]` 和 `values[]`，按日期排序取最新

### 步骤2：搜索外部宏观数据

并行执行以下 WebSearch 查询（freshness 设为 d7）：

1. `美元指数 DXY 最新` — 获取DXY最新值、前值、趋势
2. `SPDR GLD gold ETF holdings tonnes` — 获取GLD持仓吨数及日/周/月变化
3. `US Treasury auction results 10-year 30-year bond` — 获取最近长债拍卖结果
4. `WGC central bank gold purchases 2026` — 获取季度央行购金数据

### 步骤 2.5：已释放事件取数（仅当用户在步骤-1 选择「更新分析」时执行）

若上次生成后有待公布重大宏观事件已释放（如美国 PCE/CPI/NFP、FOMC 决议、GDP 初值），且用户选择「更新分析」，必须抓取该事件**实际公布值**与市场即时反应，纳入本次分析：

1. WebSearch 查询事件名称 + 日期（例：`美国 7月 核心PCE 公布 2026年8月`），提取：实际值 vs 预期、前值、市场即时反应（金价/美元指数/美债收益率/利率期货的变动）。
2. 在"步骤3"逐项分析时，对受该事件直接影响的指标（通常为 #1 实际利率、#2 DXY、#3 美联储政策预期）更新为事件后最新值，并标注"PCE公布后"等时间锚点。
3. 在报告中新增"数据已更新"横幅（置于整体评估横幅下方），说明：事件已于 HH:MM 北京公布、实际读数、对金价/各指标的具体影响、对原判断的修正。
4. 将元数据文件对应事件的 `released` 置为 true，避免重复触发。

> **美国宏观数据公布时区换算（务必准确，禁止套用错误时区）**：
> - PCE / CPI / PPI / 非农就业(NFP) / 季度GDP初值：惯例于**美东时间 8:30** 公布 → 夏令时(EDT, UTC-4)=**北京 20:30**；冬令时(EST, UTC-5)=**北京 21:30**。
> - FOMC 利率决议 / 点阵图：于**美东 14:00** 公布 → **北京次日 02:00**（夏令）/ **次日 03:00**（冬令）。
> - 杰克逊霍尔等央行行长演讲：以官方公布北京时间为准（例：沃什演讲 北京 22:00）。
> 生成"近期事件日历"时，每条必须换算为准确北京时间并区分"已公布/待公布"。

### 步骤3：逐项分析与标注

对每项指标按以下框架分析并标注利多/利空/中性。详细分析框架见 `references/analysis_framework.md`。

**标注规则：**
- **利多**：该指标当前状态有利于金价上涨
- **利空**：该指标当前状态不利于金价上涨
- **中性**：该指标当前状态对金价影响不明确或多空平衡
- **强利多**：该指标出现极端利多信号（如创历史新高/新低、结构性变化）
- **传统利空/关系失效**：传统框架下应利空，但因市场主线切换导致与金价关系失效

### 步骤4：判断市场主线

检查是否存在"美国主权债务风险溢价主导"场景，判断条件：
- 实际利率上升但金价同步上涨（负相关失效）
- 美债长端收益率创多年新高
- 联邦债务突破关键整数关口
- 财政部采取非常规操作（如扩容回购）
- 知名投资者公开警告债务危机

若以上条件满足2项以上，市场主线判定为"主权债务风险溢价"，需在综合总结中单独说明实际利率与金价传统负相关关系失效。

### 步骤5：生成HTML看盘网页

使用 `assets/dashboard_template.html` 作为基础模板生成完整HTML看盘网页。模板含占位符（`__XAU_PRICE__`、`__GC_PRICE__`、`__AU_PRICE__` 等），用 Python 脚本做字符串替换注入最新数据后输出，替换完成后必须检查无残留 `__XXX__` 占位符。页面结构（自上而下）：

1. **Header**：标题、数据时间戳、伦敦金现最新价格（移动端自动换行至标题下方）
2. **三地金价卡片行**：伦敦金现（XAU/USD 现货）+ 纽约金（COMEX GC 主力连续，附12月合约价）+ **国内金价（沪金期货主力 AU0，附 SGE AU9999 与 AUTD）**

   国内金价卡片以沪金期货主力价 `__AU0_PRICE__` 作为主要展示价格（实际交易金价），副信息区放 AU9999（`__AU_PRICE__`）与 AUTD（`__AUTD_PRICE__`），不做灰色淡化处理。三地卡片均不带 emoji 标志。
3. **整体评估横幅**：格局判断（偏利多/偏利空/中性震荡）+ 一句话描述
4. **6张指标卡片**（桌面2列网格，移动端1列）：指标名称、当前值、前值、变化趋势、利多/利空/中性标签、逻辑说明、详细数据表
5. **特别风险提示框**（黄色警告框）：若市场主线为主权债务风险溢价，说明实际利率与金价负相关关系失效
6. **综合总结**：多空力量对比表、核心逻辑链、近期事件日历、风险提示
7. **页脚**：数据来源、免责声明

**响应式排版要求（手机+电脑兼容，模板已内置，勿破坏）：**
- `viewport` meta 含 `viewport-fit=cover`；`html` 设置 `-webkit-text-size-adjust:100%` 防移动端字体自动放大
- 标题/价格用 `clamp()` 弹性字号；表格套 `.table-wrap`（overflow-x:auto）允许小屏横向滚动
- ≤768px：金价卡片/指标卡片/评估横幅转单列，header 金价块转流式布局；≤480px：卡片头部转纵向堆叠
- K线图为 Canvas 自绘（无外部CDN依赖），宽度100%自适应，触摸事件 `touch-action:pan-y` 保证页面可滚动

**颜色规范（遵循中国市场惯例）：**
- 利多/涨：红色系（#dc3545）
- 利空/跌：绿色系（#28a745）
- 中性：灰色（#6c757d）
- 强利多：深红色（#c82333）
- 金色点缀：#ffd700

### 步骤6：输出与交付 + 写入元数据

将生成的HTML文件保存到工作目录，**统一命名为 `gold_dashboard_YYYY-MM-DD.html`**（北京时间当日日期，便于步骤-1 去重与时效闸门）。

**同时写入同日元数据文件 `gold_dashboard_YYYY-MM-DD.meta.json`**，供下次调用检测"待公布事件是否已释放"：

```json
{
  "generated_at": "YYYY-MM-DDTHH:MM:SS+08:00",
  "pending_events": [
    {"name": "美国7月核心PCE", "release_at": "YYYY-MM-DDTHH:MM:SS+08:00", "released": false}
  ]
}
```

- `pending_events` 仅记录"当天或稍后公布、且尚未释放的同档期重大宏观事件"（PCE/CPI/NFP/FOMC/GDP/财报季焦点等）。已公布的事件不写入，或在重新生成时置 `released:true`。
- `release_at` 必须用**北京时间 ISO8601** 精确填写（时区换算见"步骤2.5"）。
- 若本次是因用户选择「更新分析」而重算，将对应已释放事件 `released` 置 true，避免下次询问时重复提示。

最后通过 `present_files` 展示 HTML，并在回复附简洁文字摘要。若任务要求发送邮件，将报告发送之。

## 数据质量规则

- 所有数据必须重新获取，不使用技能中的历史示例值
- 时间戳转换为北京时间（GMT+8）
- 概率同时展示原始小数和百分比
- 两组数据长度不一致时只配对共同长度
- 储备数据按日期排序后取最新，不取数组首/尾元素
- 标注逻辑说明时附带一句简短因果关系，不延伸为投资建议
- 三地金价需注明数据口径（现货/期货合约、收盘价/夜盘价、数据源），不同源价格略有差异属正常
- 生成后校验无残留占位符、JS可通过语法检查
